> and the Cycle lifecycle screens. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> file says otherwise; the only palette addition is `--warning` (see Color).

`src/styles/globals.css` (tokens read from the working tree, not re-asked), `CLAUDE.md` conventions

## Spacing Scale

Declared values (multiples of 4), unchanged from Phase 1:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-text gap inside cards/rows, avatar-stack overlap offset, badge padding |
| sm | 8px | Gap between meta items on a card, gap between cards in a column, row internal gap |
| md | 16px | Column padding, dialog/panel section padding, gap between Board columns |
| lg | 24px | Peek panel outer padding, page header to content gap |
| xl | 32px | Desktop row and control height (`h-8`), List row height, group header height |
| 2xl | 48px | Cycles-list row height (`min-h-12`), gap between page sections |
| 3xl | 64px | Not used (no page-level hero areas in this phase) |

Exceptions:
- **44px (`h-11`) touch targets below `md`**: List rows, My Pulses rows, Cycles-list rows, every icon-only button, the Board card's minimum height, the peek panel close button, dialog footer buttons. Inherited from Phase 1 D-05.
- **12px (`p-3`)** inner padding on Board cards only. It is a multiple of 4, but not a named token; it gives the Linear-compact density in D-08.
- **Column width** is a layout dimension, not spacing: `w-5/6` (about 83%) below `md` for snap-scroll (D-19, the "about 85%" is approximated with a scale value because arbitrary values are banned), `w-72` (288px) from `md`.
- **Peek panel width**: `w-full` below `md`, `md:max-w-2xl` (672px) from `md`.

## Color

All colors are existing semantic tokens from `src/styles/globals.css`. No hex values or arbitrary
color classes appear in components.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#000000` (`bg-background`) | Page, sidebar, Board/List canvas, column backgrounds (columns are transparent, no fill) |
| Secondary (30%) | `#16181C` (`bg-card` / `bg-muted` / `bg-secondary`) | Pulse cards, peek panel and dialog surfaces, popovers, active Tabs trigger, row hover fill (`hover:bg-muted`), property picker triggers |
| Accent (10%) | `#1D9BF0` (`bg-primary`, `text-primary`, `ring-ring`) | See "Accent reserved for" |
| Destructive | `#F4212E` (`text-destructive`, `bg-destructive`) | Overdue due date (D-08), "Overdue" Cycle badge, Delete Pulse button. Nothing else. |
| Success | `#00BA7C` (`text-success`) | Done status icon, Verified state in the peek panel, "Active" Cycle badge text |
| Warning (NEW token) | `#FFAD1F` (`--warning`) with `--warning-foreground` `#000000` | Returned marker and callout (D-10), "Ending soon" Cycle badge |
| Muted text | `#71767B` (`text-muted-foreground`) | Meta text, inactive status icons, placeholders |
| Border | `#2F3336` (`border-border`) | Card borders, dividers, dashed empty/drop-target outlines |

**New token, added to `src/styles/globals.css`:** `--warning: #ffad1f;` and
`--warning-foreground: #000000;` in `:root`, plus `--color-warning` and `--color-warning-foreground`
in `@theme inline`. Used as `text-warning`, `border-warning/40`, `bg-warning/10` (opacity modifiers
on semantic tokens are allowed; arbitrary values are not). Reason: D-10 asks for a warning-style
"Returned" treatment and blue must stay sparing; destructive red would misread a Founder's note as an
error.

Accent reserved for (exhaustive):
1. The single primary button per screen: "New Pulse" (My Pulses, Cycle), "New Cycle" (Cycles list), "Find a Trial Cycle" (My Pulses empty), "Create Pulse" / "Create Cycle" (dialog submit), "Verify Pulse" (peek panel, Founder). Start now / Close Cycle / Return Pulse are `outline`, never primary.
2. Text links: "Open in Cycle" / "Open in Board" and Proof Link URLs. Cycle row titles and Pulse titles are `text-foreground`, never accent.
3. Focus rings (`ring-ring`), including the keyboard-lift outline during a dnd-kit keyboard drag.
4. The drop-position insertion line (2px, `bg-primary`) shown between cards/rows while dragging.

Everything else is white/grey on black: status icons (except Done in `text-success`), priority
icons, avatars, Tabs, badges other than those named above, and secondary buttons.

Status icons (lucide): Todo `Circle`, In progress `CircleDot`, Review `CircleDashed`, Done
`CircleCheck` (`text-success`); the other three use `text-muted-foreground`, and the icon of the
group/column the user is dragging over uses `text-foreground`. Priority icons: low `SignalLow`,
medium `SignalMedium`, high `SignalHigh`, all `text-muted-foreground` (high uses `text-foreground`).
No priority set renders no icon.

## Layout and Interaction Contract

### Shared row/card data (D-08)

One `PulseRow` data shape feeds Board cards, List rows and My Pulses rows: title, status, priority,
assignee, `dueAt`, Proof Link count, `reviewNote`, plus context label for My Pulses only.

| Element | Board card | List row / My Pulses row |
|---------|-----------|--------------------------|
| Container | `rounded-lg border border-border bg-card p-3`, stacked, min height `min-h-11` below `md` | `flex items-center gap-2 px-2`, `h-8` from `md`, `min-h-11` below `md`, `hover:bg-muted`, full-row click target |
| Title | Body 14/400, `line-clamp-3` | Body 14/400, `truncate flex-1 min-w-0` |
| Meta line | Second line, Label 12/400 `text-muted-foreground`: priority icon, due date (only when set; `text-destructive` when past `dueAt` and status not done), Link icon + count (only when > 0), `Returned` Badge (`text-warning border-warning/40`) when `reviewNote` set and status is todo/in progress | Same items inline on the right, in this order: Returned, due, Proof Links, avatar. Below `md` they wrap to a second line under the title. |
| Assignee | Rounded-square Avatar `size-5` (20px) bottom-right of meta line; unassigned renders a dashed-border empty avatar | Same, right-aligned |
| Context label (My Pulses only) | n/a | `Startup · Cycle` or `Startup · Trial Cycle`, Label 12/400 muted, `truncate max-w-48`, after the title; title keeps layout priority |
| Description | Never shown (no excerpt) | Never shown |

Clicking a card/row (pointer distance under the drag threshold, or Enter/Space on the focused
element) sets `?pulse=<id>` and opens the peek panel.

### My Pulses (WORK-01, D-01 to D-05)

- Page: `h1` "My Pulses" (Display) left; "New Pulse" primary Button right (hidden when the caller can see no Cycle). Shows a `ShortcutHint` "C".
- Groups in fixed order: **In progress, Review, Todo, Done**. Each group header is a `Collapsible` trigger: status icon, name (Heading 16/600), count (Label, tabular-nums), chevron. Groups with zero items are not rendered. In progress, Review and Todo start open; **Done starts collapsed** and, when open, shows at most `MY_PULSES_RECENT_DONE_LIMIT` (constant in `constants.ts`, recommended 10, most recently updated first) with a Label footer "Showing your {N} most recent".
- Review group label reads "Review" (the glossary word is Submitted Pulse; the column name stays "Review").
- Order inside a group (D-04, tie-break recommended): rank ascending, then `updatedAt` descending; Pulses without a rank sort last. No drag handles, no drag.
- Rows are flat across Startups, never sub-grouped (D-02). No row is draggable.
- Clicking a row opens the peek panel in place; the panel header links "Open in Cycle" / "Open in Board" (accent link) to the Pulse's home screen.
- `C` on this screen opens the quick-create dialog with the Cycle picker (D-07).

### Cycles list `/s/$slug/cycles` (WORK-04, D-13, D-14, D-17)

- Page: `h1` "Cycles" (Display) left; "New Cycle" primary Button right for Founders only (hidden for Members).
- Sections in order: **Active, Planned, Closed**. Section headers use the group header style (Heading, count, chevron). Active and Planned start open; **Closed starts collapsed**. A section with zero Cycles is not rendered.
- Row: `min-h-12` (48px), a router `Link`. Left: title (Body 14/400 `truncate`) with the date range under it (Label 12 muted, `Mar 3 – Mar 17`); optional badge "Ending soon" (`text-warning`) or "Overdue" (`text-destructive`) from the existing `cycleUrgency`. Right: progress `done/total` (Label, tabular-nums, e.g. `4/12`), Cycle Member avatar stack (max 4 avatars, overlapping by `-space-x-1`, then a `+N` chip), and for Founders a `MoreHorizontal` row menu (`DropdownMenu`) containing "Start now" (planned) or "Close Cycle" (active), and "Open".
- Members see only Cycles they belong to; Founders see all (backend-scoped, UI does no filtering).

### Cycle screen `/s/$slug/cycles/$cycleId` (WORK-02, WORK-04, D-14 to D-16, D-18)

Header (wraps to stacked rows below `md`, never truncates controls):
1. Title (Display 20/600, `truncate`) + status Badge (Planned: `secondary`; Active: `outline` with `text-success`; Closed: `outline` muted).
2. Meta row (Label muted): date range, `done/total` progress, avatar stack button (opens Members popover).
3. Controls right (below `md`: full-width row): Board/List `Tabs` (defaults to **Board on every visit, all breakpoints**; not persisted, no `?view=`), "New Pulse" primary (`ShortcutHint` C), and for Founders "Start now" (planned) or "Close Cycle" (active) as `outline` Buttons. Closed Cycle: no "New Pulse", no Start/Close, Board and List are read-only (no drag, peek fields read-only).

Board (desktop and mobile):
- Container: horizontal flex, `gap-4 overflow-x-auto`, fills the remaining viewport height (`min-h-0 flex-1`). Four columns in order Todo, In progress, Review, Done. Each column: `w-5/6 shrink-0 snap-center` below `md` (horizontal scroll-snap on the container, `snap-x snap-mandatory`), `md:w-72 md:snap-align-none` from `md`.
- Column: header (status icon, name Heading 16/600, count) sticky at the top; body is a vertical `overflow-y-auto` stack of cards with `gap-2`. Column body has a min height so an empty column is still a drop target. Empty column: dashed-border block with Label "No Pulses".
- Done column: Verified Pulses show the `CircleCheck` success icon on the card meta line.
- Card actions: none visible (Linear-compact). No grip handle; the whole card is the drag activator. Keyboard: focus the card, Space lifts, arrow keys move between columns/positions, Space drops, Esc cancels (dnd-kit `KeyboardSensor` with `sortableKeyboardCoordinates`).

List (all breakpoints):
- Same four groups as collapsible sections (all open by default), using the shared row component at row height above. Empty group: header with count 0 plus a dashed "No Pulses" row that is also the drop target.
- Rows can be dragged between groups and reordered within a group (D-20). Status can also be changed from the peek panel (accessible non-drag path).

Sensors (Claude's discretion, recommended defaults): `PointerSensor` with `activationConstraint: { distance: 8 }`; `TouchSensor` with `{ delay: 250, tolerance: 8 }` (long press, D-19); `KeyboardSensor`. `autoScroll` on with the default threshold so dragging near a screen edge scrolls to the neighbouring snap column. Drag preview is a `DragOverlay` copy of the card with `shadow-lg` and `border-ring`; the source card stays in place at `opacity-40`.

### Drag feedback (D-21)

- On drag start every column/group is evaluated with the shared `canDrop`/`kanbanMove` rules plus the Proof Link gate (D-12).
- **Allowed target:** normal opacity, dashed `border-muted-foreground` outline while hovered, and the insertion line (`bg-primary`, 2px) at the drop position.
- **Disallowed target:** `opacity-40`, `cursor-not-allowed`. While the pointer is over it, its body shows one Label line with the reason from `kanbanMove`, e.g. "Only a Founder can verify a Pulse, once it is in review", "This Pulse is awaiting review", "Verified Pulses are final", "Add a Proof Link first". Dropping there animates the overlay back to the source and changes nothing. An `aria-live` announcement repeats the reason (custom dnd-kit `announcements` using Pulse titles and column names).
- **Founder drops:** a Submitted Pulse into Done runs Verify immediately (optimistic). A Submitted Pulse into In progress opens the Return dialog (note required); cancelling snaps the card back.
- **Optimistic move + rollback:** the card moves on drop. If the backend rejects, the change reverts and a `toast.error` shows the backend's message verbatim.

### Peek panel (WORK-03, D-03, D-09 to D-12, D-24)

- Trigger/URL: `?pulse=<id>` via `validateSearch` on the My Pulses and Cycle routes. Closing (Esc, overlay click, close button) removes the param. Opening a different Pulse swaps content without closing.
- Container: `Sheet` `side="right"`, `w-full` below `md` (full-screen), `md:max-w-2xl` from `md`. Body scrolls; the review footer is sticky.
- Header row: context label (`Startup · Cycle`, Label muted), "Open in Cycle" / "Open in Board" accent link (shown on My Pulses; on a Cycle screen it is omitted), overflow menu (Founders and the creator: "Delete Pulse"), and a close `X` (44px below `md`).
- Two-column body from `md` (content left, property column right, `w-48`); below `md` the properties form a top block above the content.
  - **Content column:** editable title (Display, click to edit, saves on blur or Enter; Esc reverts), editable description (Textarea, placeholder "Add a description...", saves on blur), **Returned callout** (D-10), **Proof Links** section (Heading "Proof Links"; list of rows with kind Badge, truncating URL as accent link opening in a new tab, remove `X` icon button; add row = URL Input + "Add" outline Button; kind inferred from the URL by `inferProofLinkKind`).
  - **Property column:** Status, Priority, Assignee, Due date — each a label (Label muted) over a picker trigger (`h-8`, `bg-secondary`, opens on click). Status and Priority use `DropdownMenuRadioGroup`; Assignee uses Popover + Command (search Cycle-visible Members, "Assign to me" first); Due date uses the native date input.
- **Inline editing:** every field saves on blur/change through the existing mutations, with no separate Edit mode (D-09). A failed save reverts the field and shows `toast.error` with the message.
- **Returned callout (D-10):** shown only while `reviewNote` is set and the Pulse is not in review/done: `rounded-md border border-warning/40 bg-warning/10 p-3`, `AlertTriangle` icon in `text-warning`, Heading-weight line "Returned by Founder", the note in Body. It disappears when the Pulse is resubmitted to review.
- **Proof gate (D-12):** in the status picker, "Review" is disabled while the Cycle Pulse has zero Proof Links, with a Tooltip and inline Label "Add a Proof Link first". Board Pulses have no Review option.
- **Founder review block (D-11):** visible only to Founders on a Pulse in Review; sticky footer with "Return Pulse" (`outline`) and "Verify Pulse" (primary). "Return Pulse" opens the Return dialog (required note). After Verify the panel shows a `CircleCheck` "Verified" line in `text-success` and locks.
- **Locked state:** in Review (assignee cannot edit), Done, Closed Cycle, or a locked Board (Verdict or end date) all fields render read-only (pickers disabled, title/description not editable) with one Label line above the content: "Locked while in review", "Verified Pulses are final", "This Cycle is closed" or "This Board is locked".
- **Board Pulse variant (D-24):** same component; no Review option in the status picker, no review block, no Proof gate, Proof Links optional; context label reads `Startup · Trial Cycle`, link reads "Open in Board".
- **Not found / no access:** replaces the body with `EmptyState` (see Copywriting) and a "Close" button.

### Quick-create dialog (D-06, D-07)

- `Dialog`, `sm:max-w-lg`. Opened by `C` (registry entry), the "New Pulse" button, or the palette row "Create Pulse".
- Fields: Title `Input` (required, autofocus, placeholder "Pulse title"). Below it one compact row (wraps below `md`): Priority (dropdown trigger, default none), Assignee (popover trigger, default **me**), Due date (native date input). On My Pulses a leading Cycle `Select` is shown (default: Focused Startup's active Cycle; lists only Cycles the caller can see; grouped by Startup). Inside a Cycle the target is fixed and shown as a Label "Adding to {Cycle title}".
- Enter in the title creates and closes. **Cmd/Ctrl+Enter** creates, keeps the dialog open, clears only the title, refocuses it and shows `toast.success("Pulse created")` with an "Open" action to `?pulse=<id>`. Footer hints use `ShortcutHint`: "Enter to create", "Cmd Enter to create another".
- Submit button "Create Pulse" (primary) shows a pending state (disabled, `Loader2` spinner, label "Creating...").
- Description is not in this dialog (added later in the peek panel).

### Start, Close and Create Cycle (WORK-04, D-14 to D-16)

- **Start now** (planned Cycle): if another Cycle in the Startup is active, `Dialog` confirm (copy below); otherwise it starts immediately with `toast.success`.
- **Close Cycle dialog:** title, a Body line with the unfinished count (todo + in progress + review, existing `isUnfinished`), then "Move unfinished Pulses to" `Select` with: each other planned or active Cycle (label = title), **"+ New Cycle"**, and "Leave in this Cycle". Choosing "+ New Cycle" reveals, in place, a compact form: Title `Input`, Start date, End date. Submit "Close Cycle" (primary). Atomic backend close-with-new-Cycle is preferred over two client calls (CONTEXT D-15). With zero unfinished Pulses the select and count are replaced by the line "All Pulses are finished."
- **Create Cycle dialog** (a `Dialog`, chosen over a Sheet because it has four short fields): Title (required, autofocus), Start date, End date (end must be after start), Members (optional multi-select: Popover + Command; chosen Members appear as removable chips; Founders are implicit and not listed). Submit "Create Cycle" (primary), `C` is not bound here.
- **Cycle Members popover (D-16):** opened from the header avatar stack. Lists implicit Founders first (Founder Badge, no remove control), then Cycle Members with a remove icon button (44px below `md`, `aria-label="Remove {name}"`). Below the list, an "Add member" trigger opens a Command combobox of Startup Members not yet in the Cycle; selecting one adds immediately (they are notified; no acceptance). Members (non-Founders) see the same list read-only without Add or Remove controls.
