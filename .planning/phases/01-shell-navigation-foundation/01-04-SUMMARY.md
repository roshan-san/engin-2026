# Phase 1 Plan 4: /s/$slug Route Skeleton and Auth/Member Gating Summary

**The pathless `_shell` -> `_authed` -> `s/$slug` -> `_member` route chain, 24 new route files (11 bare stubs, 3 unchanged pages, the rest layouts/redirects), and `/` plus Google sign-in retargeted to `/my-pulses` — all built while the old `/app` tree stays mounted and untouched.**

## Accomplishments

- `ShellLayout`/`AuthedLayout` (`src/shell/layout/AuthLayouts.tsx`) pick `AppShell` vs `PublicShell` by `useConvexAuth()`, matching the proven component-level gating pattern (`AppLayout.tsx`) rather than `beforeLoad` — no chrome flash while auth loads (UI E11).
- `useStartupBySlug` + `StartupRouteLayout`/`useStartupRoute` (`src/shell/hooks/`, `src/shell/startup/StartupRoute.tsx`) resolve a Startup by its URL slug and focus it for Members only when `!isFocused` (edge SHELL-02/idempotency); every `/s/$slug` descendant reads `{slug, result, member}` from context, never from `focusedStartupId` (edge SHELL-02/concurrency).
- `MemberGate` (`src/shell/startup/MemberGate.tsx`) sends non-Members, unknown slugs and Stealth Startups alike to the public Pitch (`/startup/$slug`) — a UX convenience only, since every Convex call behind these screens still re-checks membership (T-01-11).
- `TrialCyclePage` + `useTrialCycle` sit outside the `_member` gate and use the existing `api.hiring.trialCycles.get` access rule, so Participants/Applicants who are not Members can still reach `/s/$slug/trials/$trialCycleId`.
- 11 stub screens (My Pulses, Inbox, Threads, Cycles, Cycle, Hiring, Trial Cycle, Team, Pitch, Activity, Settings, Edit profile) render `StubScreen` with UI-SPEC's exact copy and no action button; `/s/$slug` redirects to `/s/$slug/cycles`; `/startups/new`, `/discover` and `/pricing` render the existing pages unchanged (D-12).
- `LandingPage`'s signed-in redirect and Explore link now point at `/my-pulses`/`/discover`; Google sign-in's `redirectTo` is the fixed `${origin}/my-pulses` (T-01-14, no user-supplied redirect target).
- The old `/app/*` tree is untouched — `pnpm build` and `pnpm check` are clean with both route trees mounted simultaneously.
