## ADR-0001: Trial Cycles are the only path into a team (besides Invites)
- source: docs/adr/0001-trial-cycles-are-the-only-path-into-a-team.md
- status: locked
- decision: There is no way to apply to a Role directly — a Role is only a listing that Trial Cycles attach to. A person becomes a Member by accepting an Offer created by a _passed with offer_ Verdict, or by a Founder's Invite. Direct role applications and the founder-side "add participant to team" action are removed because they let people onto teams without a Verdict and without the person's consent. Offers never expire; only the Founder can withdraw them. When a Role reaches its Headcount, pending Offers for it are withdrawn, not-yet-started Trial Cycles for it are cancelled, and running ones finish but can no longer produce _passed with offer_. One attempt per person per Trial Cycle; a second chance means joining a later Trial Cycle for the same Role.
- scope: Trial Cycles, Role, Offer, Verdict, Member, Invite, Headcount

## ADR-0002: Score counts only Founder-confirmed evidence
- source: docs/adr/0002-score-counts-only-founder-confirmed-evidence.md
- status: locked
- decision: Score increases only from Founder-confirmed evidence: a passed Verdict or an accepted Offer from a Trial Cycle. Joining and sitting in a Trial Cycle earns nothing; team conversions count only Offers accepted from Trial Cycles, not Invites. Counting self-marked pulses and "completed" (closed) trials was the original implementation; it let anyone farm Score by joining open-admission Trial Cycles, so open admission removal was rejected in favour of gating Score on Verdicts. Amendment (2026-09-26): originally each Verified trial Pulse was worth +10 and closing a Trial Cycle required a decision on every Submitted Pulse. Two changes made that untenable — per-participant Boards (ADR 0003) mean Participants split their own Pulses, so a per-Pulse reward invites splitting work into many trivial Pulses and buries Founders in reviews; the Verdict already judges the whole Submission, so trial Pulses are now a record of *how* someone worked, with no per-Pulse review. Internal Cycles have a real review → done gate but are not a Score source, since anyone can create a Startup, invite friends and verify their own Pulses — internal Verified Pulses appear on the profile as Proof of Work only (revisit once Startup verification exists). Weights: passed Verdict +80, accepted Offer +120, Leaving an active Trial Cycle −40 (floor 0). Leaving is public on the profile; Founder Cancellation carries no penalty. Closing a Trial Cycle requires a Verdict for every Participant.
- scope: Score, Founder-confirmed evidence, Trial Cycles, Verdicts, Offers, Pulses, Participant Boards, Internal Cycles

## ADR-0003: Each Participant gets a private Board
- source: docs/adr/0003-each-participant-gets-a-private-board.md
- status: locked
- decision: Each Participant in a Trial Cycle works on their own private Board, seeded with copies of the Founder's Challenges, which they then own entirely (split, edit, add, move); only that Participant and the Startup's Founders can see it. A Trial Cycle tests every Participant on the same problem, and the point is to see how each person breaks down and executes work, not only the final result — a shared trial board let Participants copy each other and hid individual approach. Communication follows the same isolation: a private Thread per Participant with the Founders, plus one-way Announcements to everyone — not a group channel. Pulses on a Board carry the owning Participant; Challenges are separate template records, copied at start and again when added mid-trial — editing a Challenge never changes copies. Boards use todo → in progress → done with no review step; the Participant's Submission (summary + Proof Links) is what the Founder judges. A Verdict, or the end date, locks the Board and Submission.
- scope: Participant, Board, Trial Cycle, Challenges, Submission, Verdict, Pulses

## ADR-0004: Code is grouped by domain, not listed flat
- source: docs/adr/0004-code-is-grouped-by-domain-not-listed-flat.md
- status: locked (frontend half of this decision is explicitly superseded by ADR-0006 per the doc's own status frontmatter; the backend grouping still stands — see `[INFO]` in the conflicts report)
- decision: Both `src/features/` and `convex/` were regrouped from a flat per-feature/per-domain listing (12+ frontend feature folders, 14 Convex root files) into six shared domain buckets — `people`, `teams`, `hiring`, `work`, `app`, `marketing` — so `features/<domain>/<feature>/` and `convex/<domain>/` mirror each other. Convex's generated `api.*` surface gains one more segment (e.g. `api.startups.*` became `api.teams.startups.*`), requiring every call site rename. Each domain was moved in its own commit. `convex/lib/` was already domain-grouped and left as-is. A handful of files stay at `convex/` root on purpose because Convex expects them there or they are cross-cutting infra, not domain logic: `schema.ts`, `http.ts`, `auth.ts`, `auth.config.ts`, `convex.config.ts`, `migrations.ts`, `notifications.ts`.
- scope: code organization, domain grouping, src/features/, convex/, API surface, people, teams, hiring, work, app, marketing

## ADR-0005: Startups pay; talent and visibility are never for sale
- source: docs/adr/0005-startups-pay-talent-and-visibility-are-never-for-sale.md
- status: locked
- decision: The Plan belongs to the Startup; Pro is a flat subscription per Startup ($10/month, shown in the buyer's local currency). Everything a person does as talent is free and unlimited: finding and joining Trial Cycles, building Score, their profile. Nobody can pay for contact or visibility — no paid messaging or outreach, no promoted Startups, Roles or Trial Cycles; Opportunities and Explore rank on merit only. Considered and rejected: limiting talent's active Trial Cycle entries (throttled the side Founders pay for), Pro-only outreach to Contributors (LinkedIn's model, easy to bypass off-platform), featured placement in Opportunities (undermines the trust that talent places in the listings). A success fee per accepted Offer was deferred as hard to price/enforce at launch. Pro only raises limits that grow with a Startup: Trial Cycle Capacity, open Roles, live Trial Cycles and Members, plus Stealth. The numbers live in `convex/lib/limits.ts`, and the pricing page lists only limits the backend actually enforces. Free is kept simple: no trials, no introductory tiers. A downgrade never takes away anything that already exists, only blocks creating more beyond Free limits. A Startup is never made public automatically. The subscription stays with the Founder who paid for it; there is no billing handover. Campus and incubator promotions are Dodo discount codes with an expiry and usage limit.
- scope: billing, pricing, talent features, marketplace, Trial Cycle limits, Pro subscription, Stealth mode

## ADR-0006: The frontend is a shell plus domain features, and URLs carry the Startup
- source: docs/adr/0006-frontend-is-a-shell-plus-domain-features.md
- status: locked
- decision: Replaces the frontend half of ADR-0004. The frontend is redesigned Linear-style: a sidebar with a bottom tab bar on mobile; one Focused Startup chosen with a switcher, plus personal areas (Inbox, My Pulses, Threads) that span every Startup; ⌘K and a few single-key shortcuts; dark only. The code splits into three parts: `src/shell/` is the app frame (sidebar, mobile tabs, switcher, command palette, shortcuts, layouts) — not a feature, no backend counterpart; `src/features/<domain>/<feature>/` holds the four backend domains (`people`, `teams`, `hiring`, `work`) and keeps mirroring `convex/<domain>/`; `discover` and `marketing` are frontend-only surfaces that compose cards from those domains. Inside a feature, page components live in `pages/` (formerly `ui/`), next to `components/`, `hooks/`, `schemas/` and `constants.ts`. The Focused Startup is carried in the URL (`/s/$slug/...`) rather than hidden server state, giving every screen and notification link a stable, shareable address; `users.activeStartupId` survives only as "last focused". There is no `/app` prefix anymore — the root layout picks the app shell or the public header based on sign-in state. Explore and Opportunities merge into one public `/discover` page with three tabs: Trial Cycles, Startups and Contributors. Backend files move to match the domain model: `people/billing.ts` → `teams/billing.ts` (the Plan is the Startup's, ADR-0005), `hiring/trialMessages.ts` → `hiring/threads.ts`, `trialCycles.maxContributors` → `capacity`. Libraries added on purpose: dnd-kit for the kanban (replacing the hand-rolled pointer drag), shadcn primitives as needed (sidebar, command, sheet, dialog, tabs, tooltip, …).
- scope: frontend architecture, shell, domain features, URL routing, Startup switcher, sidebar navigation
